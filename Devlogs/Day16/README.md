# Project J 개발일지

---

## 16일차 : 사용자 설정 저장·복원 및 로그·코딩 규칙 확정

---

### 개발 목표

그래픽, 오디오, 조작 설정을 하나의 사용자 설정 데이터로 관리하고 JSON 파일에 저장하여 게임을 다시 실행해도 이전 설정이 복원되도록 구성했다.

프로젝트 공통 로그에 등급 필터를 추가하고, 이후 런타임 코드에 적용할 C# 작성 규칙과 로그 사용 기준을 문서로 확정했다.

---

### 주요 작업 내용

- 사용자 설정 저장 데이터 형식 추가
- 설정 전용 `Settings` 폴더와 JSON 읽기·쓰기 기능 추가
- 최초 실행 시 기본 설정 파일 자동 생성
- 손상되거나 지원하지 않는 설정 파일의 기본값 복구
- 그래픽 품질, 해상도, 화면 모드, 수직 동기화 및 목표 프레임 저장·적용
- 마스터·배경 음악·효과음 음량과 전체 음소거 저장·복원
- 마우스 감도, 게임패드 시점 속도 및 수직 시점 반전 저장·적용
- Input System 바인딩 재지정 JSON 저장·복원 기반 추가
- 프로젝트 로그 최소 출력 등급 필터 추가
- C# 작성 규칙, 로그 형식 및 설정 저장 규칙 문서화
- 서비스 초기화 순서를 저장 → 설정 → 오디오 순서로 정리

---

### 사용자 설정 구조

| 분류 | 저장 항목 |
|---|---|
| 그래픽 | 품질 단계 이름, 해상도, 화면 모드, 수직 동기화, 목표 프레임 |
| 오디오 | 마스터 음량, 배경 음악 음량, 효과음 음량, 전체 음소거 |
| 조작 | 마우스 감도, 게임패드 시점 회전 속도, 수직 시점 반전 |
| 입력 | Input System 바인딩 재지정 JSON |
| 로그 | 최소 출력 로그 등급 |
| 호환성 | 설정 파일 버전 |

설정 파일은 게임 진행 저장과 분리하여 다음 위치에 저장하도록 구성했다.

```text
Application.persistentDataPath/Settings/user-settings.json
```

설정 변경 시 다음 순서로 처리한다.

```text
설정값 입력
→ 유효 범위 보정
→ 실행 중인 게임에 즉시 적용
→ JSON 파일 저장
→ 관련 시스템에 변경 이벤트 전달
```

### 서비스 초기화 순서

| 순서 | 서비스 | 역할 |
|---:|---|---|
| 100 | `SaveService` | 저장 및 설정 폴더 준비, JSON 파일 입출력 |
| 200 | `SettingsService` | 사용자 설정 읽기, 검증, 복구 및 그래픽 적용 |
| 300 | `AudioService` | 저장된 오디오 설정 적용 |
| 400 | `DataValidationService` | 프로젝트 데이터 검증 |

저장 폴더를 먼저 준비한 뒤 설정을 읽고, 복원된 음량을 오디오 서비스가 적용하도록 초기화 의존성을 정리했다.

---

### 그래픽 설정 저장과 복원

`SettingsService`가 실행 시 설정 파일을 읽어 다음 그래픽 항목을 적용하도록 확장했다.

- 그래픽 품질 단계
- 화면 가로·세로 해상도
- 전체 화면 모드
- 수직 동기화 간격
- 목표 프레임 수

그래픽 품질은 플랫폼이나 프로젝트 설정 변경으로 인덱스 순서가 달라질 수 있으므로 숫자가 아닌 품질 단계 이름으로 저장한다.

설정 파일이 없으면 현재 실행 환경을 기준으로 기본 설정을 생성한다. JSON이 손상되었거나 설정 버전이 지원되지 않으면 기본값으로 복구하고 정상 파일을 다시 저장할 수 있도록 구성했다.

---

### 오디오 설정 저장과 복원

`AudioService`가 `SettingsService`의 저장값과 변경 이벤트를 사용하도록 수정했다.

| 항목 | 적용 상태 |
|---|---|
| 마스터 음량 | `AudioListener.volume`에 즉시 적용 |
| 전체 음소거 | 실제 전체 출력에 즉시 적용 |
| 배경 음악 음량 | 저장·복원 및 향후 믹서 연결용 값 관리 |
| 효과음 음량 | 저장·복원 및 향후 믹서 연결용 값 관리 |

현재 구조에서는 마스터 음량과 음소거가 실제 출력에 적용된다. 배경 음악과 효과음의 개별 음량은 이후 `AudioMixer`를 연결할 수 있도록 설정 데이터와 공개 변경 메서드를 마련했다.

---

### 조작 설정과 입력 재지정

`ThirdPersonCameraController`가 저장된 조작 설정을 불러와 실행 중인 카메라에 적용하도록 변경했다.

- 마우스 시점 감도
- 게임패드 시점 회전 속도
- 수직 시점 반전

설정 서비스가 없는 상태에서 Game 씬을 직접 실행하면 기존 Inspector 값을 사용하고, 서비스가 준비되어 있으면 저장값과 변경 이벤트를 연결한다.

`PlayerInputReader`에는 Input System의 바인딩 재지정 내용을 JSON으로 저장하고 복원하는 기반을 추가했다. 특정 액션의 바인딩을 변경하거나 전체 재지정을 기본값으로 되돌릴 수 있으며, 이후 설정 UI가 해당 기능을 호출할 수 있다.

---

### 로그 등급 체계

| 등급 | 사용 기준 |
|---|---|
| `Verbose` | 반복 가능한 상세 개발 진단 |
| `Info` | 서비스 초기화와 설정 적용 등 중요한 정상 흐름 |
| `Warning` | 기본값 복구 후 계속 진행할 수 있는 문제 |
| `Error` | 저장 실패나 필수 에셋 누락 등 현재 기능을 진행할 수 없는 문제 |
| `Off` | 프로젝트 공통 로그 전체 비활성화 |

저장된 최소 로그 등급보다 낮은 메시지는 Unity Console에 출력하지 않는다. 기존 공통 로그 형식은 유지했다.

```text
[ProjectJ][Category][UPPER_SNAKE_CODE] message
```

### 확인 항목

- Bootstrap 실행 시 서비스가 저장 → 설정 → 오디오 순서로 초기화되는지 확인
- 최초 실행 시 `user-settings.json`이 생성되는지 확인
- 게임 재실행 후 그래픽·오디오·조작 설정이 유지되는지 확인
- 마스터 음량과 전체 음소거가 실제 출력에 적용되는지 확인
- 마우스 감도와 수직 시점 반전이 카메라에 적용되는지 확인
- 입력 바인딩 재지정 후 재실행해도 변경 내용이 유지되는지 확인
- 손상된 JSON을 기본값으로 복구하고 정상 파일을 다시 저장하는지 확인
- 설정 파일 버전이 맞지 않을 때 기본값으로 복구하는지 확인
- 최소 로그 등급보다 낮은 로그가 출력되지 않는지 확인
- 기존 이동·점프·달리기·앉기·밀치기·부활 기능이 유지되는지 확인
- Unity Console에 컴파일 오류와 반복 예외가 없는지 확인
- Windows 개발 빌드에서 설정 저장·복원이 유지되는지 확인

Unity 에디터의 실제 컴파일, Play Mode 및 Windows 빌드 통과 여부는 로컬 실행 결과로 최종 확인한다.
