# Project J 개발일지

---

## 15일차 : 프로토타입 통합 검증 및 플레이어 상태·외부 힘 모듈 분리

---

### 개발 목표

현재까지 구현한 이동, 점프, 달리기, 앉기, 높이 측정, 체크포인트, 추락, 부활, 밀치기, 경기 타이머, 순위 및 결과 기능을 통합 검증했다.

검증 결과를 바탕으로 여러 스크립트에 흩어져 있던 플레이어 행동 제어를 상태 모듈로 통합하고, 밀치기와 같은 외부 힘을 이동 입력과 분리할 수 있도록 플레이어 구조를 개선했다.

---

### 주요 작업 내용

- Unity 컴파일 오류와 누락된 컴포넌트 확인
- EditMode 및 PlayMode 자동 테스트 실행
- 이동·점프·달리기·앉기 기능 통합 점검
- 높이·체크포인트·추락·부활 흐름 점검
- 더미 밀치기, 재사용 대기시간 및 피격 면역 점검
- 10분 경기 타이머, 순위 및 결과 화면 점검
- 경기 종료 후 플레이어 행동 차단 점검
- Windows 개발 빌드 생성 및 실행 테스트
- 플레이어 상태 관리 모듈 분리
- 플레이어 외부 힘 처리 모듈 분리
- 부활 및 경기 종료 코드의 상태 제어 방식 통합
- 더미 전용 밀치기 구조를 공통 외부 힘 수신 구조로 변경

---

### 플레이어 구조 개선

| 모듈 | 담당 기능 |
|---|---|
| `PlayerInputReader` | 키보드와 마우스 입력값 제공 |
| `PlayerStateController` | 정상 플레이·부활·경기 종료 상태 관리 |
| `PlayerMovementController` | 걷기·달리기·점프·앉기 및 최종 이동 처리 |
| `ExternalForceReceiver` | 외부 힘을 받을 수 있는 대상의 공통 기반 제공 |
| `PlayerExternalForceController` | 플레이어가 받은 밀치기 속도·감속·피격 면역 처리 |
| `PlayerRespawnController` | 추락 감지·체크포인트 복귀·부활 상태 전환 |
| `PlayerPushController` | 밀치기 대상 탐색 및 외부 힘 전달 |

기존에는 부활이나 경기 종료 시 입력, 이동, 밀치기 컴포넌트를 각각 비활성화했다. 이를 `PlayerStateController`가 현재 상태에 따라 행동 가능 여부를 제공하는 방식으로 변경했다.

플레이어의 최종 이동은 다음 세 속도를 결합하도록 구성했다.

```text
입력 이동 속도 + 외부 힘 속도 + 수직 속도
                         ↓
               CharacterController.Move()
```

이 구조를 통해 이동 입력과 밀치기 반응이 서로 독립적으로 작동하며, 이후 실제 플레이어나 네트워크 기반 밀치기를 추가할 수 있는 기반을 마련했다.

### 상태 전환 구조

```text
정상 플레이
→ 추락 감지
→ 부활 상태
→ 체크포인트 이동
→ 정상 플레이

정상 플레이 또는 부활 상태
→ 경기 시간 종료
→ 경기 종료 상태
```

부활 상태에서는 이동, 점프, 달리기, 앉기 및 밀치기를 차단하고 부활이 완료되면 정상 플레이 상태로 복구한다. 경기 종료 상태에서는 부활 완료 처리가 진행되더라도 플레이어 행동이 다시 활성화되지 않도록 구성했다.

### 통합 테스트 항목

- `WASD` 이동과 마우스 시점 회전
- `Space` 점프
- `Left Shift` 달리기와 스태미나 소비·회복
- `Left Ctrl` 앉기와 낮은 천장 아래 일어서기 차단
- 경사면·계단·발판 가장자리 이동
- 현재 높이와 최고 높이 갱신
- 체크포인트 활성화와 추락 후 복귀
- 부활 중 입력 차단과 부활 후 입력 복구
- 가장 가까운 대상 하나에 대한 밀치기 판정
- 벽 뒤 및 사거리 밖 대상 밀치기 차단
- 밀치기 재사용 대기시간과 피격 면역
- 더미 추락 후 시작 위치 복귀
- 경기 타이머와 실시간 순위 갱신
- 최종 결과 화면 표시
- 경기 종료 후 이동·점프·밀치기 차단
- Windows 개발 빌드 실행과 반복 예외 로그 확인
