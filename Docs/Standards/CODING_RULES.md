# Project J 코딩·로그 규칙

---

## C# 작성 규칙

- 중괄호는 선언문과 조건문 다음 줄에 배치하는 Allman 스타일 사용
- 런타임 코드는 `ProjectJ` 루트 네임스페이스 아래 기능별 네임스페이스 사용
- 파일 하나에 핵심 공개 형식 하나만 작성하고 파일명과 형식명 일치
- Inspector 노출 필드는 `public` 대신 `[SerializeField] private` 사용
- 외부 읽기 속성은 공개하고 외부 쓰기는 메서드를 통해 처리
- 상수는 `PascalCase`, private 필드는 `camelCase`, 공개 형식과 메서드는 `PascalCase` 사용
- 숫자와 문자열을 반복해서 직접 쓰지 않고 상수 또는 설정 데이터로 분리
- `Update`, `LateUpdate`, `FixedUpdate` 안에서 반복적인 객체 검색과 메모리 할당 금지
- 필수 참조 누락은 시작 단계에서 검사하고 해당 기능을 안전하게 중단
- 저장 데이터는 버전 필드를 포함하고 읽은 직후 유효 범위 검증
- 코드의 각 줄에 초보자도 이해할 수 있는 짧은 한글 명사형 주석 작성

## 로그 출력 규칙

16일차 이후 새로 작성하거나 수정하는 런타임 코드에서는 `Debug.Log`를 직접 호출하지 않고 `ProjectLog`를 사용합니다. 기존 코드는 해당 파일을 수정하는 일차에 같은 규칙으로 교체합니다.

| 등급 | 사용 기준 | 예시 |
|---|---|---|
| `Verbose` | 반복될 수 있는 상세 진단 정보 | 입력 장치 변경, 임시 상태값 |
| `Info` | 정상적인 중요 흐름의 시작·완료 | 서비스 초기화, 설정 적용 |
| `Warning` | 기본값 복원 등으로 계속 진행 가능한 문제 | 손상 설정 복구, 선택 데이터 누락 |
| `Error` | 현재 기능을 정상 진행할 수 없는 문제 | 필수 에셋 누락, 저장 실패 |
| `Off` | 모든 프로젝트 로그 출력 중단 | 최종 배포의 완전 비활성화 |

## 로그 형식 규칙

```text
[ProjectJ][Category][UPPER_SNAKE_CODE] message
```

- 분류는 `ProjectLogCategory` 값 사용
- 코드는 영문 대문자와 밑줄로 작성
- 같은 원인은 항상 같은 코드 사용
- 메시지는 발생 상황과 확인 대상을 짧고 구체적으로 작성
- 복구 가능한 문제를 `Error`로 출력하지 않음
- 정상 프레임마다 `Info`를 반복 출력하지 않음
- 민감 정보, 인증 정보, 개인 식별 정보는 로그에 기록하지 않음

## 설정 저장 규칙

- 사용자 설정 파일은 `Application.persistentDataPath/Settings/user-settings.json` 사용
- 그래픽·오디오·조작·입력 재지정·최소 로그 등급을 하나의 JSON으로 저장
- 설정 변경 직후 유효 범위 보정, 런타임 적용, 파일 저장 순서 유지
- 손상되거나 읽을 수 없는 설정은 기본값으로 복구
- 품질 단계는 플랫폼마다 인덱스가 달라질 수 있으므로 이름으로 저장
- 입력 재지정은 Input System의 binding override JSON 사용
- 게임 진행 저장과 사용자 설정 저장 폴더 분리
